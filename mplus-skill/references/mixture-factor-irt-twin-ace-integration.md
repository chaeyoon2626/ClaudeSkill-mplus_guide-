# Factor (IRT) Mixture and Twin ACE Models Using Numerical Integration

> Source: Mplus User's Guide v8, Chapter 7, Examples 7.27, 7.28, 7.29

## One-line summary
Covers three `TYPE = MIXTURE` designs that all require `ALGORITHM = INTEGRATION` because a continuous factor is regressed on, or embedded within, a categorical latent variable: a binary-class factor (IRT) mixture model that relaxes plain LCA's conditional-independence assumption by letting a within-class factor (with class-varying loadings) explain leftover correlation among binary/ordinal indicators (Ex 7.27); a two-group MZ/DZ twin threshold-liability model for a single categorical outcome per twin, using `KNOWNCLASS` for zygosity and `MODEL CONSTRAINT` to decompose the outcome's liability covariance into ACE (Additive genetic / Common environment / unique Environment) components (Ex 7.28); and the same twin ACE logic extended to a multi-item IRT-based liability factor per twin instead of a single observed outcome (Ex 7.29).

## Prerequisite checklist
- [ ] Decide which of the three designs fits: (a) a single-group IRT/factor mixture meant to relax LCA's conditional-independence assumption (Ex 7.27); (b) a twin/paired-unit ACE model for one categorical outcome per twin (Ex 7.28); (c) a twin ACE model where each twin's liability is itself a multi-indicator IRT factor rather than a single observed outcome (Ex 7.29)
- [ ] For Ex 7.27: confirm the indicators are binary/ordinal class indicators and that you specifically want to test/allow within-class correlation via a factor whose loadings are permitted to differ by class, rather than assuming the standard LCA conditional-independence default
- [ ] For Ex 7.28/7.29: confirm the data are structured as twin (or other genetically-informative paired-unit) records with one row per pair, parallel indicator sets for twin 1 and twin 2, and a zygosity variable coded so monozygotic (MZ) and dizygotic (DZ) pairs can be separated (e.g., `dz` coded 0/1)
- [ ] Understand that all three designs need `ALGORITHM = INTEGRATION` because a continuous factor is involved together with a categorical latent variable (class or known-class) and/or categorical outcomes under maximum likelihood — this is markedly more computationally demanding than plain LCA/LPA, and cost grows with the number of integration dimensions (number of factors) and sample size
- [ ] Be ready to use `MODEL CONSTRAINT` with `NEW(...)` to define genetic/environmental variance-decomposition parameters (a, c, and for Ex 7.29 also e) plus a derived heritability parameter h that are not directly estimated model parameters
- [ ] Decide on `LINK` (default logit vs. `PROBIT`): the classic threshold/liability ACE model (Ex 7.28) uses `LINK = PROBIT` because it assumes normally-distributed latent response variables underlying the categorical outcomes; Ex 7.29 leaves the default logit link, giving a two-parameter logistic (2PL) IRT model for each twin's liability factor instead

## Option selection logic
| Situation | Choice |
|---|---|
| Binary/ordinal LCA indicators show leftover within-class correlation that plain conditional-independence LCA can't capture, and you want an IRT-style factor whose loadings vary by class | Ex 7.27 design: `f BY u1-u8; [f@0];` in `%OVERALL%`, then in each `%c#k%` block free the loadings (`f BY u1@1 u2-u8;`), the factor variance (`f;`), and the thresholds (`[u1$1-u8$1];`) |
| Want to test heritability of a single categorical (binary/ordinal) outcome measured once per twin | Ex 7.28 design: `CLASSES = cdz(2); KNOWNCLASS = cdz (dz = 0 dz = 1);`, one single-indicator factor per twin (`f1 BY u1; f2 BY u2;`), `LINK = PROBIT;`, and an ACE decomposition in `MODEL CONSTRAINT` |
| Want heritability of a latent trait measured by several categorical items per twin, rather than by one observed outcome | Ex 7.29 design: multi-indicator factors per twin (`f1 BY u11 u12-u14 (lam2-lam4); f2 BY u21 u22-u24 (lam2-lam4);`) with loadings and thresholds equated across twin 1/twin 2 via shared labels, default logit link (2PL IRT), and an ACE decomposition that adds a residual/unique-environment term e |
| Need to identify which pairs are MZ vs. DZ using an observed zygosity variable rather than estimating class membership | `CLASSES = cdz(2); KNOWNCLASS = cdz (dz = 0 dz = 1);` — assigns pairs to known classes directly from the data instead of via estimated posterior probabilities |
| Need factor loadings and/or thresholds forced equal between twin 1 and twin 2 (assuming the two members are measured on the same scale) | Give the corresponding `BY`/threshold statements for each twin the same parenthesized label (or label list via the list function, e.g. `(lam2-lam4)`, `(t1-t4)`) |
| Need the factor covariance (i.e., the covariance of the liabilities) to differ between MZ and DZ groups while everything else stays equal | Put separate `f1 WITH f2 (covmz);` / `f1 WITH f2 (covdz);` statements in the class-specific `%cdz#1%` / `%cdz#2%` blocks (different labels), while loadings/thresholds/variances stay equated via `%OVERALL%`-level labels |
| Model runs into a singular factor covariance matrix because the factor variance and the factor covariance end up numerically identical | Add a small constant to the variance formula in `MODEL CONSTRAINT` (e.g., `varf = a**2 + c**2 + .001;`) as a numerical safeguard |
| Want a heritability estimate with a standard error, without that quantity constraining the model itself | Define it as an extra `NEW` parameter in `MODEL CONSTRAINT` that is purely a function of the other new parameters (e.g., `h = a**2/(a**2 + c**2 + 1);`), not tied to any observed variable |

## Menu path & screen fields
1. **VARIABLE:**
   - Ex 7.27: `NAMES = u1-u8; CATEGORICAL = u1-u8; CLASSES = c (2);`
   - Ex 7.28: `NAMES = u1 u2 dz; CATEGORICAL = u1 u2; CLASSES = cdz (2); KNOWNCLASS = cdz (dz = 0 dz = 1);`
   - Ex 7.29: `NAMES = u11-u14 u21-u24 dz; CATEGORICAL = u11-u24; CLASSES = cdz (2); KNOWNCLASS = cdz (dz = 0 dz = 1);`
2. **ANALYSIS:**
   - All three: `TYPE = MIXTURE; ALGORITHM = INTEGRATION;`
   - Ex 7.27 additionally: `STARTS = 100 20;` (larger-than-default initial/final-stage start counts)
   - Ex 7.28 additionally: `LINK = PROBIT;`
3. **MODEL:**
   - Ex 7.27: `%OVERALL%` — `f BY u1-u8; [f@0];`; then `%c#1%` — `f BY u1@1 u2-u8; f; [u1$1-u8$1];`; then `%c#2%` — `f BY u1@1 u2-u8; f; [u1$1-u8$1];`
   - Ex 7.28: `%OVERALL%` — `[u1$1-u2$1] (1); f1 BY u1; f2 BY u2; [f1-f2@0]; f1-f2 (varf);`; then `%cdz#1%` — `f1 WITH f2 (covmz);`; then `%cdz#2%` — `f1 WITH f2 (covdz);`
   - Ex 7.29: `%OVERALL%` — `f1 BY u11 u12-u14 (lam2-lam4); f2 BY u21 u22-u24 (lam2-lam4); [f1-f2@0]; [u11$1-u14$1] (t1-t4); [u21$1-u24$1] (t1-t4);`; then `%cdz#1%` — `f1 WITH f2 (covmz);`; then `%cdz#2%` — `f1 WITH f2 (covdz);`
4. **MODEL CONSTRAINT** (Ex 7.28 and 7.29 only):
   - Ex 7.28: `NEW(a c h); varf = a**2 + c**2 + .001; covmz = a**2 + c**2; covdz = 0.5*a**2 + c**2; h = a**2/(a**2 + c**2 + 1);`
   - Ex 7.29: `NEW(a c e h); var = a**2 + c**2 + e**2; covmz = a**2 + c**2; covdz = 0.5*a**2 + c**2; h = a**2/(a**2 + c**2 + e**2);`
5. **OUTPUT:** `TECH1 TECH8;` in all three examples

## Sub-option details
- `f BY u1-u8; [f@0];` (Ex 7.27, `%OVERALL%`) : defines the factor f as measured by all 8 binary/ordinal indicators, with its mean fixed at zero (implying a mean of zero in both classes); the factor represents individual variation in response probabilities *within* class, relaxing the plain LCA assumption of conditional independence among indicators given class. The factor variance is held equal across classes by default.
- Class-specific `f BY u1@1 u2-u8; f; [u1$1-u8$1];` (Ex 7.27) : each `%c#k%` block relaxes the equality constraints (imposed by default from `%OVERALL%`) separately for the factor loadings, the factor variance, and the indicator thresholds — this is what makes the model an IRT *mixture* (i.e., a factor/IRT model whose measurement parameters are class-specific) rather than a single-class IRT model; the guide describes this as equivalent to allowing loadings from f to the u's to vary across c (illustrated in the source diagram with broken arrows from c to the f→u paths).
- `ALGORITHM = INTEGRATION;` (all three) : selects a maximum-likelihood estimator with robust standard errors via numerical integration, required whenever a continuous factor interacts with a categorical latent variable and/or categorical outcomes under ML; Ex 7.27 uses one dimension of integration (one factor) at the default 15 integration points, while Ex 7.28 and 7.29 use two dimensions (two factors, one per twin) at 225 integration points; the `ESTIMATOR` option can select a different estimator if needed.
- `STARTS = 100 20;` (Ex 7.27) : requests 100 random sets of starting values at the initial stage and 20 optimizations carried through to the final stage, larger than the program default of 20 initial-stage / 4 final-stage sets — appropriate given the added complexity of a class-varying-loading factor mixture, to guard against settling on a local rather than global maximum.
- `KNOWNCLASS = cdz (dz = 0 dz = 1);` (Ex 7.28, 7.29) : identifies `cdz` as a categorical latent variable whose class membership is *known* rather than estimated, defined from the observed variable `dz`; individuals with `dz = 0` are placed in class 1 (monozygotic twins in these examples) and those with `dz = 1` in class 2 (dizygotic twins) — this turns the two-group twin design into a mixture model with fixed, data-determined group assignment instead of estimated posterior class probabilities.
- `LINK = PROBIT;` (Ex 7.28) : overrides the default logit link for categorical outcomes with a probit link, needed because the threshold model for liabilities (Neale & Cardon, 1992) that this example implements assumes normally-distributed latent response variables underlying the categorical outcomes u1/u2; Ex 7.29 does not override the link, so it stays at the default logit, yielding a two-parameter logistic (2PL) IRT model for the twins' liability factors instead of the probit-liability parameterization.
- `f1 BY u1; f2 BY u2;` with `[f1-f2@0];` and `f1-f2 (varf);` (Ex 7.28) : defines one single-indicator factor per twin member because, under ML estimation, direct covariances between categorical outcomes are not part of the model — routing each outcome through its own factor lets the *factor* covariance stand in for the covariance between the categorical outcomes (equivalently, the covariance of the latent response variables/liabilities underlying u1 and u2). Both factor means are fixed at zero and their variances are held equal across the MZ/DZ groups via the shared label `varf`. The variance of each underlying liability equals the factor variance plus one, since one is the fixed residual variance in the probit regression of the outcome on the factor.
- `[u1$1-u2$1] (1);` (Ex 7.28) : the label `(1)` holds the thresholds of u1 and u2 equal across the two twins within a pair, reflecting the assumption that both twins are measured on the same scale.
- `f1 WITH f2 (covmz);` / `f1 WITH f2 (covdz);` in `%cdz#1%` / `%cdz#2%` (Ex 7.28, 7.29) : gives the MZ group and the DZ group their own, separately labeled factor covariance — `covmz` for monozygotic pairs, `covdz` for dizygotic pairs — since the entire ACE logic hinges on MZ pairs (who share 100% of segregating genes) and DZ pairs (who share on average 50%) having systematically different expected covariances.
- `f1 BY u11 u12-u14 (lam2-lam4); f2 BY u21 u22-u24 (lam2-lam4);` and `[u11$1-u14$1] (t1-t4); [u21$1-u24$1] (t1-t4);` (Ex 7.29) : the list-function labels `(lam2-lam4)` assign the same loading labels to twin 1's and twin 2's parallel items (loading for u12 equated to loading for u22, and so on), and `(t1-t4)` does the same for the four thresholds per item — so both twins' liability factors are measured identically, and the two-parameter logistic IRT model (Muthén, Asparouhov, & Rebollo, 2006) that results is symmetric across pair members; the first loading of each factor (u11, u21) is implicitly fixed to define the metric, since only loadings 2–4 are freed via labels while an intercept-style first indicator anchors the scale.
- `MODEL CONSTRAINT: NEW(a c h); ...` (Ex 7.28) : `NEW` introduces parameters a and c that are not directly estimated model parameters but are defined algebraically to decompose the twin covariance structure into additive-genetic (a) and shared/common-environmental (c) components; `varf = a**2 + c**2 + .001;` reconstructs the (equated) factor variance from a and c, with the `+ .001` added purely as a numerical safeguard to avoid a singular factor covariance matrix that would otherwise arise because the factor variances and covariances would coincide; `covmz = a**2 + c**2;` and `covdz = 0.5*a**2 + c**2;` encode the classic ACE expectation that MZ pairs share the full additive-genetic variance while DZ pairs share only half of it; `h = a**2/(a**2 + c**2 + 1);` computes heritability as the proportion of total liability variance (using the fixed residual variance of 1 for the underlying probit response) attributable to a, without itself constraining any other parameter.
- `MODEL CONSTRAINT: NEW(a c e h); ...` (Ex 7.29) : the same ACE logic as Ex 7.28, extended with a third parameter e representing unique/non-shared environmental variance, since here the factors have their own freely estimated loadings/residual structure rather than a fixed residual variance of 1; `var = a**2 + c**2 + e**2;`, `covmz = a**2 + c**2;`, `covdz = 0.5*a**2 + c**2;`, and `h = a**2/(a**2 + c**2 + e**2);` mirror Ex 7.28's formulas but with e folded into both the total variance and the heritability denominator.

## Post-run operations
- For Ex 7.27, compare the class-specific factor loadings, factor variances, and thresholds against each other (via `TECH1` to confirm which parameters were actually freed) to judge whether the IRT-mixture extension meaningfully changes the picture versus a plain conditional-independence LCA (see `mixture-lpa-lca-cross-sectional.md`); if within-class loadings/variances end up similar across classes, the added factor may not be earning its complexity.
- For Ex 7.28 and 7.29, check `TECH1` to confirm that the intended labels (thresholds/loadings equated across twins, `varf`/`var` equated across zygosity groups, `covmz`/`covdz` left distinct) were assigned as planned before trusting the ACE decomposition.
- Read the `MODEL CONSTRAINT` output for the new parameters a, c, (e), and h directly — h is the point estimate of heritability with its own standard error, letting you judge both the magnitude and the statistical support for a genetic contribution to the outcome (Ex 7.28) or latent trait (Ex 7.29).
- Since `ALGORITHM = INTEGRATION` is used throughout, verify convergence carefully and consider whether the number of integration points or (for Ex 7.27) the number of random starts needs to be increased if results look unstable or if a better-fitting solution might exist at a different set of starting values; runtimes will be markedly longer than for plain LCA/LPA given the added integration dimensions.
- For Ex 7.28 vs. Ex 7.29, decide which is the more defensible test of heritability for your data: a single observed categorical outcome per twin (7.28, simpler, probit threshold/liability model) versus a multi-item IRT-based liability factor per twin (7.29, richer measurement but heavier computationally) — consider whether your outcome is genuinely multi-item before committing to the 7.29 design.

## Likely FAQ mapping
- "My binary/ordinal LCA indicators seem correlated within class beyond what the classes already explain — can I add a factor to soak that up?" → Ex 7.27's factor (IRT) mixture design: `f BY u1-u8;` in `%OVERALL%` with class-specific loadings/variance/thresholds freed in each `%c#k%` block
- "How is this different from adding `WITH` statements between continuous indicators in a mixture model?" → `WITH` statements (see `mixture-as-device-correlated-zip-semiparametric.md`, Ex 7.22) directly free indicator covariances for continuous indicators; the Ex 7.27 factor approach instead routes the within-class correlation among binary/ordinal indicators through a single factor whose loadings can differ by class, which is the IRT-mixture parameterization
- "I have twin/sibling pair data with a diagnosis or other binary outcome and want to estimate heritability" → Ex 7.28's two-group MZ/DZ threshold-liability ACE model: `KNOWNCLASS = cdz (dz = 0 dz = 1);`, `LINK = PROBIT;`, single-indicator factors per twin, and an ACE `MODEL CONSTRAINT`
- "My twin outcome is really a multi-item scale, not a single observed variable — can I still do an ACE decomposition?" → Ex 7.29 extends the same twin ACE logic to a multi-indicator IRT factor per twin, adding a residual/unique-environment parameter e since loadings are freely estimated rather than fixed
- "How do I assign twins to MZ/DZ groups directly from a zygosity variable instead of letting the model estimate class membership?" → `CLASSES = cdz (2); KNOWNCLASS = cdz (dz = 0 dz = 1);`, used identically in both Ex 7.28 and 7.29
- "How do I get a heritability estimate with a standard error out of Mplus?" → define it as a `NEW` parameter in `MODEL CONSTRAINT` that is a function of the other new (genetic/environmental) parameters, e.g. `h = a**2/(a**2 + c**2 + 1);`, without letting it constrain any other model parameter
- "Why does my factor/twin mixture model need `ALGORITHM=INTEGRATION` and take so much longer than my earlier LCA runs?" → any model combining a continuous factor with a categorical latent variable or categorical outcomes under ML needs numerical integration; cost scales with the number of factors (integration dimensions) and sample size, which is why Ex 7.28/7.29's two-factor twin models (225 integration points) are heavier than Ex 7.27's one-factor model (15 points)
