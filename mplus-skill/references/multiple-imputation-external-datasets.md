# Analyzing Externally Imputed Multiple-Imputation Data Sets

> Source: Mplus User's Guide v8, Chapter 13, Example(s) 13.13

## One-line summary
Runs one analysis model across a whole set of already-imputed data sets (e.g. produced outside Mplus, or produced by Mplus's own `DATA IMPUTATION` command in an earlier job) by pointing `DATA: FILE` at a small text file that just lists the imputed data sets' file names, with `DATA: TYPE = IMPUTATION;` telling Mplus to treat that file as a list rather than as raw data.

## Prerequisite checklist
- [ ] Do you already have a set of imputed data sets (each a complete, separately saved rectangular data file) rather than a single raw data file with missing values?
- [ ] Were the imputed data sets created outside Mplus (e.g. by another statistical package), or by Mplus's own `DATA IMPUTATION` command in a previous run? (Either source works the same way at analysis time — see the note below.)
- [ ] Do you have (or can you create) a single plain-text list file, one imputed data set's file name per line, covering all imputations to be analyzed?
- [ ] Do all imputed data sets share exactly the same variables, in the same order/format, as declared in `VARIABLE: NAMES ARE ...;`?

## Option selection logic
| Situation | Choice |
|---|---|
| You have several complete imputed data sets and a model to fit to all of them, combining results | `DATA: FILE IS implist.dat; TYPE = IMPUTATION;` where implist.dat lists each imputed data set's file name, one per line |
| The list file needs to be created by hand (e.g. imputations came from another program) | write the list file yourself: one imputed data set name per line, in a plain-text file |
| The imputations were generated by Mplus's own `DATA IMPUTATION` command | the list file is created automatically as part of that job; see `missing-data-mechanisms-imputation.md` for generating it |
| You just want to combine an existing set of imputations with a substantive model, without ever having only one raw data file with missing values | this file's `TYPE = IMPUTATION;` workflow — no `MISSING =` declaration is needed since the imputed files are already complete |

## Menu path & screen fields
1. **TITLE:**
2. **DATA:**
   - `FILE IS implist.dat;` — the list file, not an imputed data set itself
   - `TYPE = IMPUTATION;` — tells Mplus the file named above is a list of imputed data set names, not raw scores
3. **VARIABLE: NAMES ARE ...;** — must match the variables actually present in each imputed data set
4. **MODEL:** the ordinary substantive model, written exactly as it would be for a single data set

## Sub-option details
- `DATA: FILE IS implist.dat; TYPE = IMPUTATION;`: the file named by `FILE IS` is not itself a data set — it is a plain-text index file where **each record/line names one imputed data set** to be analyzed, e.g.:
  ```
  imp1.dat
  imp2.dat
  imp3.dat
  imp4.dat
  imp5.dat
  ```
  Mplus fits the same `MODEL:` to every listed data set in turn.
- The list file **must be created by the user** unless the imputations were produced with Mplus's `DATA IMPUTATION` command in the same or an earlier job, in which case the list file is generated automatically as part of that imputation step (see `missing-data-mechanisms-imputation.md` for the `DATA IMPUTATION` / `SAVE =` syntax that produces it).
- No `MISSING =` handling is required at the analysis stage here, because each listed data set is already a complete (imputed) rectangular file — missingness was already resolved during the imputation step itself, not during this analysis.
- Combining results across the imputed data sets: parameter estimates are averaged across the set of per-imputation analyses, and standard errors are computed from the average of the per-imputation standard errors plus the between-imputation parameter-estimate variation (Schafer, 1997) — the same combination rule used for Mplus-generated imputations.

## Post-run operations
- Confirm the output reports the number of imputed data sets actually analyzed, and that it matches the number of lines in the list file (a mismatch usually means a file name in the list could not be found/read).
- Check that reported parameter estimates and standard errors reflect the multiple-imputation-combined values (averaged estimates; SEs incorporating between-imputation variance), not just a single imputation's results.
- If any individual imputed data set fails to converge, examine which one before trusting the combined results — a poorly imputed data set can be diagnosed by comparing per-imputation output if available.

## Likely FAQ mapping
- "I imputed my data in another program (e.g. R, SAS) — can Mplus analyze all the imputed data sets and combine the results?" → yes: build a plain-text list file naming each imputed data set, then `DATA: FILE IS list.dat; TYPE = IMPUTATION;`
- "What exactly goes inside the list file?" → one imputed data set's file name per line/record, nothing else
- "Do I still need a MISSING = statement?" → no, each imputed data set is already complete
- "How is this different from just running DATA IMPUTATION and analyzing right away in one job?" → `DATA IMPUTATION` followed immediately by a substantive `MODEL:` in the *same* run does imputation and analysis in one job (see `missing-data-mechanisms-imputation.md`); `TYPE = IMPUTATION;` here is for *reusing* a previously created (or externally created) set of imputed files in a separate run
