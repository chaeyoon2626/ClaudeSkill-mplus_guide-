# Parameterization of Models with More Than One Categorical Latent Variable

> Source: Mplus User's Guide v8, Chapter 14 (Special Modeling Issues) — this chapter contains no numbered Examples; it is a technical-discussion chapter. Section used: Parameterization of Models with More Than One Categorical Latent Variable (Logit Parameterization, Loglinear Parameterization, Probability Parameterization)

## One-line summary
When a `TYPE=MIXTURE` model has two or more categorical latent variables (e.g., a two-time-point LTA/hidden-Markov model, or any model relating several latent class variables to each other), Mplus offers three interchangeable ways to parameterize the relationships between them — `LOGIT` (a set of multinomial-logistic-regression-style `ON`/intercept statements; the default), `LOGLINEAR` (a loglinear model of the joint frequency table using only `WITH` statements), and `PROBABILITY` (direct probability parameters) — and `TECH15` turns any of these into the actual marginal/conditional (including transition) probability tables.

## Prerequisite checklist
- [ ] Does the model have two or more categorical latent variables (e.g., `c1`, `c2`, ...) declared under `TYPE = MIXTURE;`, related to each other via `ON` or `WITH` statements in `MODEL:`?
- [ ] How many classes does each categorical latent variable have? (the worked examples in the manual use two variables with 3 classes each)
- [ ] Do you want the relationship between the latent variables expressed as regression-style logits (`LOGIT`), as a loglinear model of the joint table (`LOGLINEAR`), or as direct probabilities (`PROBABILITY`)?
- [ ] Do you need the actual (marginal/conditional/transition) probability table out of the model, in addition to whichever parameterization was used to specify it? (this needs `TECH15`, and if covariates are involved, potentially the LTA Calculator in the Mplus Editor)
- [ ] Is this in service of a latent transition analysis (LTA) / hidden Markov model specifically? If so, see `latent-transition-analysis-hidden-markov.md` for the example-level syntax (this file is the underlying general parameterization reference that file points back to).

## Option selection logic
| Situation | Choice |
|---|---|
| Relationship between categorical latent variables should be written as a set of (multinomial) logistic regressions, e.g. `c2 ON c1;` | `ANALYSIS: PARAMETERIZATION = LOGIT;` — this is the **default** when `TYPE=MIXTURE` is used with more than one categorical latent variable |
| Want to model the joint frequency table of the categorical latent variables directly, including allowing association (not just regression) structure | `ANALYSIS: PARAMETERIZATION = LOGLINEAR;` — relationships specified only with `WITH` statements (not `ON`) |
| Want parameters expressed directly as probabilities rather than as logits or log-linear association terms | `ANALYSIS: PARAMETERIZATION = PROBABILITY;` — relationships specified with `ON` statements, but the estimated quantities are probabilities |
| Need the actual marginal and conditional probabilities (including latent transition probabilities) out of a `LOGIT`-parameterized mixture model | `OUTPUT: TECH15;` |
| Need conditional (e.g., transition) probabilities at specific covariate values, for a `LOGIT`-parameterized model with covariates | Mplus Editor's built-in "LTA calculator" (Mplus menu → LTA calculator), which computes these from the model's logit-with-covariates parameterization (Muthén & Asparouhov, 2011) |
| Building a two-time-point (or more) hidden Markov / LTA model | See `latent-transition-analysis-hidden-markov.md` for the worked `%OVERALL%`/`MODEL cg:`/threshold-invariance syntax; this file explains what the underlying `c2 ON c1` / `c2 WITH c1` / probability parameters actually mean |

## Menu path & screen fields
1. **VARIABLE:** `CLASSES = c1 (3) c2 (3);` (or however many categorical latent variables/classes the model needs)
2. **ANALYSIS:**
   - `TYPE = MIXTURE;`
   - `PARAMETERIZATION = LOGIT;` (default) or `LOGLINEAR;` or `PROBABILITY;`
3. **MODEL:**
   - `%OVERALL%` block containing the relationship statements between the categorical latent variables:
     - `LOGIT`/`PROBABILITY` parameterizations: `ON` statements, e.g. `c2#1 ON c1#1; c2#1 ON c1#2; c2#2 ON c1#1; c2#2 ON c1#2;`
     - `LOGLINEAR` parameterization: `WITH` statements only, e.g. `c2#1 WITH c1#1; c2#1 WITH c1#2; c2#2 WITH c1#1; c2#2 WITH c1#2;`
   - Intercepts for the non-reference classes, e.g. `[c2#1]; [c2#2];` and `[c1#1]; [c1#2];`
4. **OUTPUT:** `TECH15;` — requests the marginal/conditional/transition probability tables implied by whichever parameterization was used

## Sub-option details
- **Three available parameterizations, in general**: (1) the logit parameterization, based on a series of logistic regressions suited to non-recursive models; (2) the loglinear parameterization, i.e. loglinear modeling of the joint frequency table; (3) the probability parameterization, which uses probabilities rather than logits.
- **LOGIT parameterization** (`PARAMETERIZATION = LOGIT;`): for two categorical latent variables with 3 classes each, the relationship is written as `ON` statements, e.g. `c2#1 ON c1#1; c2#1 ON c1#2; c2#2 ON c1#1; c2#2 ON c1#2;` — 4 slope parameters plus 2 intercepts (`[c2#1]`, `[c2#2]`) = 6 parameters total describing the conditional distribution of `c2` given `c1` when both have 3 classes. For each class `r` of `c2`, the transition probability from class `j` of `c1` is an unordered multinomial logistic regression: `P(c2=r|c1=j) = exp(a_r + b_rj) / sum_j`, where the last class of `c2` is the reference class (its intercept and all its slopes are fixed at 0), and `sum_j` is the sum of the exponentiated log odds across the classes of `c2`, for `c1 = j`. Concretely, with intercepts `a1=[c2#1]`, `a2=[c2#2]` and slopes `b11=c2#1 ON c1#1`, `b12=c2#1 ON c1#2`, `b21=c2#2 ON c1#1`, `b22=c2#2 ON c1#2`, the log odds of `c2=1` vs. `c2=3` given `c1=1` is `a1+b11`, given `c1=2` is `a1+b12`, and given `c1=3` (the reference class of `c1`) is just `a1`; symmetric expressions hold for `c2=2` vs. `c2=3`, and the log odds of `c2=3` vs. itself is always 0. `TECH15`, used together with `TYPE=MIXTURE` and `PARAMETERIZATION=LOGIT`, produces the resulting marginal and conditional probabilities (including latent transition probabilities) for the categorical latent variables. When covariates are involved, conditional (including transition) probabilities at chosen covariate values can instead be computed with the LTA calculator, available from the Mplus Editor's Mplus menu (logit parameterization with covariates is described in Muthén & Asparouhov, 2011).
- **LOGLINEAR parameterization** (`PARAMETERIZATION = LOGLINEAR;`): the relationship between the categorical latent variables is instead described with `WITH` statements only, e.g. `c2#1 WITH c1#1; c2#1 WITH c1#2; c2#2 WITH c1#1; c2#2 WITH c1#2;` (association/interaction parameters `w_rj`, analogous in count to the `LOGIT` slopes) together with the same intercepts (`a11=[c1#1]`, `a12=[c1#2]`, `a21=[c2#1]`, `a22=[c2#2]`). The joint probabilities for every cell of the `c1`×`c2` table are then obtained via the same multinomial-logistic-style formula used for `LOGIT`, but summed over all nine cells of a 3×3 table (for the 3-class-by-3-class example), with each cell's log odds built from the relevant intercepts plus, where applicable, the association parameter for that cell; the cell where both variables are at their reference class has log odds fixed at 0.
- **PROBABILITY parameterization** (`PARAMETERIZATION = PROBABILITY;`): the relationship is again written with `ON` statements (e.g. `c2#1 ON c1#1; c2#1 ON c1#2; c2#1 ON c1#3; c2#2 ON c1#1; c2#2 ON c1#2; c2#2 ON c1#3;`), but for 3-class-by-3-class variables this yields **six probability parameters directly** (one fewer than the number of cells per row, since each row's probabilities must sum to 1) rather than logits — e.g. the conditional probability of `c2=1` given `c1=1` is a directly-estimated parameter `p11`, of `c2=1` given `c1=2` is `p21`, and so on; the probability of the reference class of `c2` for each row of `c1` is not separately parameterized (it's `1 -` the sum of that row's estimated probabilities). The marginal probabilities of `c1` are referred to via `[c1#1]; [c1#2];` as usual.
- **`TECH15` output**: used in conjunction with `TYPE=MIXTURE` and (as demonstrated) `PARAMETERIZATION=LOGIT` to request marginal and conditional probabilities, including latent transition probabilities, for the categorical latent variables in a model. This is generally the more directly interpretable output than the raw logit/loglinear coefficients themselves.
- **Cross-reference**: this general parameterization machinery underlies latent transition analysis (LTA) / hidden Markov modeling, where `c1`, `c2`, ... represent the same latent classification measured at successive occasions and `c(t) ON c(t-1)` gives the transition structure; see `latent-transition-analysis-hidden-markov.md` for worked Chapter 8 examples (measurement invariance across occasions, mover-stayer structures, covariate effects on transitions, and `PARAMETERIZATION=PROBABILITY` used directly for transition probabilities).

## Post-run operations
- Request `TECH15` whenever the substantive interest is in actual probabilities (marginal class probabilities, conditional probabilities, or transition probabilities) rather than in the raw logit/loglinear/probability-parameterization coefficients themselves — this is almost always the more useful output to report.
- When covariates predict the categorical latent variables under `PARAMETERIZATION=LOGIT`, use the Mplus Editor's LTA calculator to get conditional/transition probabilities at specific, substantively meaningful covariate values, rather than hand-computing the softmax at every value of interest (compare with the by-hand multinomial-logit computation shown in `categorical-mediators-probability-conversion.md`, which uses the same underlying formula).
- If switching between parameterizations to check a result (e.g., `LOGIT` vs. `PROBABILITY`), verify that the resulting `TECH15` probability tables agree numerically — they describe the same underlying joint/conditional distribution, just parameterized differently, so a real discrepancy points to a specification error rather than a legitimate difference in results.
- Under `PARAMETERIZATION=LOGLINEAR`, remember that only `WITH` statements (not `ON`) are valid for specifying the relationship between the categorical latent variables — using `ON` there is a specification error, not just a stylistic choice.
