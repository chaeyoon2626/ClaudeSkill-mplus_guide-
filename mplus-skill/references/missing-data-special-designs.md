# Missing Data Analysis — General Options, Data Missing by Design, Multiple Cohort Design

> Source: Mplus User's Guide v8, Chapter 14 (Special Modeling Issues) — this chapter contains no numbered Examples; it is a technical-discussion chapter. Sections used: Missing Data Analysis, Data Missing by Design, Multiple Cohort Design, Rearrangement of the Multiple Cohort Data

## One-line summary
Describes the general missing-data machinery Mplus applies automatically (ML estimation under MCAR/MAR, WLS coverage rules, non-ignorable modeling, standard-error computation), how to get a first-pass missing-data descriptive summary, and how to treat data that is missing *by design* — including the accelerated/cohort-sequential longitudinal case handled with the `DATA COHORT` command.

## Prerequisite checklist
- [ ] Is missingness plausibly MCAR/MAR (can depend on observed covariates and observed outcomes), or is there a specific reason to suspect NMAR?
- [ ] What variable types are involved (continuous, censored, binary, ordered categorical, nominal, count, or a mix)? This affects which missing-data machinery applies.
- [ ] Which estimator is planned — maximum likelihood (FIML) or weighted least squares? WLS handles missingness differently for censored/categorical outcomes.
- [ ] Are any covariates themselves missing on some subjects? (covariates are treated specially — see Sub-option details)
- [ ] Is the missingness a planned feature of the study design (e.g., different instrument forms per subgroup, planned-missing subsets, or a multiple-cohort/accelerated longitudinal design) rather than incidental nonresponse?
- [ ] For a multiple-cohort design specifically: is `TYPE=GENERAL` with maximum-likelihood being used (required), and is `ALGORITHM=INTEGRATION` avoided (the cohort-rearrangement approach is not available together with it)?
- [ ] For step-by-step multiple-imputation or NMAR selection/pattern-mixture model syntax, see `missing-data-mechanisms-imputation.md` (Ch.11) — this file covers the cross-cutting mechanics and the design-driven missingness cases that Ch.11 does not.

## Option selection logic
| Situation | Choice |
|---|---|
| Continuous/censored/binary/ordered categorical/nominal/count outcomes, missingness plausibly MCAR or MAR | No special missing-data command needed beyond `MISSING = ...;` — maximum-likelihood (FIML) estimation handles this by default |
| Censored or categorical outcomes estimated with weighted least squares | Missingness is allowed to depend on the observed covariates but not on the observed outcomes; with no covariates in the model this reduces to a pairwise-present analysis |
| Suspect missingness is non-ignorable (NMAR), and want to model it with maximum likelihood using missingness indicators predicted by latent variables | ML-based non-ignorable missing-data model (Muthén, Jo, & Brown, 2003; Muthén et al., 2011) — for the concrete selection-model / pattern-mixture-model syntax pattern, see `missing-data-mechanisms-imputation.md` |
| Non-normal continuous outcomes with missing data, want robust SE/chi-square | `ESTIMATOR = MLR;` — gives the Yuan and Bentler (2000) T2* chi-square test statistic for non-normal continuous outcomes under missingness |
| Want a first look at how much data is missing and in what pattern, before modeling | `ANALYSIS: TYPE = BASIC;` — reports the number of missing-data patterns and the coverage (proportion non-missing) for each variable and each pair of variables |
| A variable pair's coverage proportion is too low for Mplus's default cutoff and the model won't estimate | `ANALYSIS: COVERAGE = value;` — changes the minimum coverage proportion required (default `.10`) |
| A covariate itself has missing values | Not modeled by default (covariates are outside the model, no distributional assumption is made about them, and missingness on them is not allowed under the default conditional-on-covariates approach); to handle covariate missingness, bring the covariate into the model as a variable with a distributional assumption (e.g., normality) instead of leaving it as a plain covariate |
| Want standard errors/confidence intervals under missing data without relying on the observed information matrix | Bootstrap standard errors and confidence intervals are available with missing data (see `analysis-command-options.md` / `output-savedata-plot-commands.md` for the general `BOOTSTRAP=`/`CINTERVAL` syntax) |
| Study design intentionally did not measure some variables for some subjects (planned-missing design, different instrument forms per subgroup, or a multiple-cohort design) | Treat it as "missing by design": flag the missing-value code with `VARIABLE: MISSING = ...;`, and declare which variables each individual should have a value for with `VARIABLE: PATTERN = ...;`; all individuals stay in the analysis, including those missing values by design |
| Longitudinal accelerated/cohort-sequential design — several birth cohorts each measured at different calendar years, and the scientific interest is development over **age**, not survey wave | `DATA COHORT:` command — rearranges the data so that age (or another time-related variable) becomes the time dimension instead of measurement occasion; only available with `TYPE = GENERAL` and only without `ALGORITHM = INTEGRATION` |

## Menu path & screen fields
These are cross-cutting `VARIABLE`/`DATA`/`ANALYSIS` options layered on top of whatever substantive model (growth, regression, CFA, etc.) is being estimated.

1. **VARIABLE:**
   - `MISSING = ALL (code);` or per-variable — declares the missing-value flag(s) in the raw data
   - `PATTERN = varlist;` — (design-driven missingness only) declares which variables each individual is expected to have a value for, based on the study design
2. **DATA:**
   - `TYPE = GENERAL;` — required if a multiple-cohort rearrangement via `DATA COHORT` will be used
   - `COHORT:` sub-block — used to rearrange a longitudinal data set from "columns = measurement occasion" to "columns = age" (see Sub-option details; this write-up covers the conceptual mechanics and the worked example from the manual, not every verbatim keyword of the `DATA COHORT` sub-block — confirm exact sub-option names against the manual or Mplus Language Generator before typing the command)
3. **ANALYSIS:**
   - `TYPE = BASIC;` — descriptive run reporting missing-data patterns and coverage
   - `COVERAGE = value;` — changes the minimum required coverage proportion (default `.10`)
   - `ESTIMATOR = ML | MLR | WLS | ...;` — governs how missingness is handled (see Option selection logic)
4. **MODEL:** the substantive model, referencing either the original repeated-measures variables or (after a `DATA COHORT` rearrangement) the new age-indexed variables Mplus creates

## Sub-option details
- **Ignorable missingness (MCAR/MAR) under ML**: available for continuous, censored, binary, ordered categorical, nominal (unordered categorical), count outcomes, or any combination of these types. MAR means missingness can be a function of observed covariates and observed outcomes.
- **Missingness under WLS estimation** (censored and categorical outcomes): missingness is allowed to be a function of the observed covariates but *not* of the observed outcomes. When there are no covariates in the model, this is analogous to a pairwise-present analysis.
- **Non-ignorable (NMAR) missing-data modeling under ML**: possible by using categorical outcomes as indicators of missingness and letting missingness be predicted by continuous and/or categorical latent variables (Muthén, Jo, & Brown, 2003; Muthén et al., 2011).
- **Robust inference under missingness**: robust standard errors and a robust chi-square test are available for all outcome types using `ESTIMATOR = MLR;`. For non-normal continuous outcomes specifically, this gives the T2* chi-square test statistic of Yuan and Bentler (2000).
- **Multiple imputation**: Mplus provides multiple imputation of missing data using Bayesian analysis (Rubin, 1987; Schafer, 1997); both an unrestricted (H1) and a restricted (H0, i.e. the substantive model) approach can be used for the imputation itself. Multiple imputed data sets can then be analyzed together with a dedicated Mplus feature that averages parameter estimates over the set of analyses and computes standard errors from the average of the within-analysis standard errors plus the between-analysis parameter-estimate variation. (Full step-by-step syntax for `DATA IMPUTATION` and reusing imputed data sets is in `missing-data-mechanisms-imputation.md`.)
- **Covariates and missingness**: in every model type, missingness is not allowed for observed covariates because they are not treated as part of the model — the model is estimated conditional on the covariates and no distributional assumptions are made about them. Covariate missingness can only be modeled if the covariate is instead brought into the model proper with a distributional assumption made about it (e.g., treated as normally distributed).
- **Standard errors under missing data**: computed using the observed information matrix (Kenward & Molenberghs, 1998). Bootstrap standard errors and confidence intervals are also available with missing data.
- **Descriptive missing-data check**: `ANALYSIS: TYPE = BASIC;` produces, as part of its output, the number of distinct missing-data patterns in the sample and the coverage — the proportion of non-missing data — for every variable individually and for every pair of variables. A default minimum coverage value of `.10` is required for a pair of variables to be usable in the model; this minimum can be changed with the `COVERAGE` option of `ANALYSIS`.
- **Data Missing by Design — concept**: occurs whenever the study design itself determines which subjects are observed on which measures, rather than data being lost to attrition/nonresponse. Named examples in the manual: (1) different forms of a measurement instrument administered to randomly selected subgroups; (2) collecting only a subset of (expensive) variables on a randomly selected subgroup of individuals rather than the full battery on everyone; (3) a multiple-cohort study where individuals measured repeatedly over time represent different birth cohorts. All of these can use the ordinary missing-data machinery — every individual, including those with by-design missing values, stays in the analysis. Mechanically this requires (a) flagging the missing-value codes via `VARIABLE: MISSING`, and (b) declaring, via `VARIABLE: PATTERN`, which variables each individual is expected to have a value for according to the design.
- **Multiple Cohort Design — concept**: longitudinal studies that collect data on several groups of individuals defined by birth year/cohort, so that development can be studied over a wider age range than the actual length of the study (an accelerated or sequential cohort design). The scientific interest is in how the outcome develops with **age**, not with measurement occasion/survey wave. When the dependent variables are on a continuous scale, Mplus can rearrange such a data set so that age (rather than time of measurement) becomes the time variable — but only for `TYPE = GENERAL` and only when `ALGORITHM = INTEGRATION` is *not* used.
- **`DATA COHORT` mechanics**: rearranges longitudinal data from a format where columns represent measurement occasions (e.g., separate variables per survey year) to a format where columns represent age (or another time-related variable). It requires knowing, for each individual, the cohort (birth year) and the year in which each measurement was taken; age at measurement is the difference between measurement year and cohort year, and age is the variable used to determine the missing-value pattern for each cohort. If an individual has no observed measurement at a particular age, that age's value is missing for that individual by design. The resulting, transformed data set is then analyzed using maximum-likelihood estimation for missing data.
- **Worked rearrangement example** (heavy drinking `HD` measured in 1982, 1983, 1987, 1989; birth cohorts 1963/1964/1965; together the cohorts span ages 17–26 even though any one cohort is measured on only four occasions):
  1. As a first step in the manual's illustration, observations without complete data on all four original measurement-occasion variables (`HD82, HD83, HD87, HD89`) are dropped before rearranging.
  2. The remaining data are then re-expressed with age-indexed columns (e.g., `HD17` … `HD26`); some age columns can be entirely absent from the rearranged set if no combination of survey year and birth cohort actually produces that age (the example has no `HD21` column for this reason).
  3. The substantive `MODEL:` command is then written using the new age-indexed variable names (e.g., `hd17`–`hd26`) instead of the original survey-year variable names, and the missing-by-design feature (asterisks/missing-value flags for the age/cohort combinations that don't exist) handles the resulting structural missingness.

## Post-run operations
- After `ANALYSIS: TYPE = BASIC;`, review the reported number of missing-data patterns and the per-variable/per-pair coverage table before committing to the substantive model; if any pair's coverage falls under the (default `.10`) minimum, either gather more data, drop that pair from the model, or explicitly raise/lower `COVERAGE=`.
- For any missing-data run, confirm the estimator matches the intended missingness assumption: plain ML/MLR for MCAR/MAR, MLR (or bootstrap) when robustness to non-normality is also needed, WLS-family only when comfortable with its covariate-only missingness restriction for censored/categorical outcomes.
- For design-driven missingness, double-check the `PATTERN` declaration reproduces the actual by-design pattern (e.g., which form/subset each subject should have) before trusting parameter estimates — a mis-specified `PATTERN` will silently treat by-design non-measurement as ordinary incidental missingness or vice versa.
- For a multiple-cohort rearrangement, verify after the `DATA COHORT` step that the number of age columns and the missingness pattern per cohort match the expected age range coverage (e.g., by cross-checking against a hand-built table like the worked example above) before fitting the age-based growth/repeated-measures model.
