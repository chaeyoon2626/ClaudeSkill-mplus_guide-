# Monte Carlo Simulation Studies — Specialized Data and Model Types

> Source: Mplus User's Guide v8, Chapter 12, Example(s) 12.5, 12.8, 12.9, 12.10, 12.11, 12.12

## One-line summary
Beyond the basic single-group, continuous-outcome internal Monte Carlo workflow (see `monte-carlo-simulation-power.md`), Chapter 12 shows how to add EFA/ESEM factors, informative missingness tied to a non-repeatable event, two-part (semicontinuous) outcomes, two-level continuous-time survival with a frailty, two-level random-slope mediation (with a constrained indirect-effect parameter), and multiple-group EFA to a simulation — each needs a few extra `MONTECARLO`/`MODEL POPULATION`/`MODEL` pieces layered on top of the standard setup.

## Prerequisite checklist
- [ ] Comfortable with the basic internal Monte Carlo recipe first (`NAMES`, `NOBSERVATIONS`, `NREPS`, `MODEL POPULATION`, `MODEL`) — see `monte-carlo-simulation-power.md`
- [ ] Know which specialized feature applies: EFA/ESEM factor structure, an event-history/survival outcome, a semicontinuous (spike-at-zero + continuous) outcome, a two-level/clustered design, a mediation path you want power for, or more than one group
- [ ] For survival variants: decide discrete-time (periodic 0/1 event indicators) vs. continuous-time (exact time-to-event, analyzed with Cox or a parametric hazard)
- [ ] For the two-part outcome: identify which binary variable(s) indicate "any vs. none" and which continuous variable(s) hold the amount when the outcome is positive
- [ ] For multilevel designs: the same `NCSIZES`/`CSIZES`/`WITHIN`/`BETWEEN` planning as in the basic file applies here too
- [ ] For multiple groups: the planned N per group and whether any parameters (loadings, intercepts, variances, factor means) should differ by group

## Option selection logic
| Situation | Choice |
|---|---|
| Simulating an EFA/ESEM factor model (rather than fixed-loading CFA) as the analysis model | `MODEL:` uses `f1 BY ... (*1);` set notation instead of ordinary `BY` statements — Example 12.5 |
| Discrete-time survival where, once the event occurs, later period indicators must be generated as missing (required for correct ML estimation of a non-repeatable event) | `MONTECARLO: MISSING = u2-u4;` + `MODEL MISSING:` logistic model that forces later indicators to be missing once an earlier one equals 1 — Example 12.8 |
| Two-part/semicontinuous outcome: a binary "any/none" part plus a continuous "amount" part that is only observed when the binary part is 1 | `MONTECARLO: GENERATE = u1-u4(1); MISSING = y1-y4;` + `MODEL MISSING:` that forces `y` missing whenever the paired `u` is 0 — Example 12.9 |
| Two-level continuous-time survival (e.g., clustered event-history data) with a Cox-type model and a cluster-level frailty | `ANALYSIS: TYPE = TWOLEVEL; BASEHAZARD = OFF;` + `MONTECARLO: GENERATE = t(s ...); HAZARDC = t(...); SURVIVAL = t(ALL);` + `%BETWEEN%` residual variance on `t` as the frailty — Example 12.10 |
| Two-level mediation where the a-path and b-path (and the total-effect c-path) are random slopes varying across clusters, and you want power for the indirect effect | `ANALYSIS: TYPE = TWOLEVEL RANDOM;` + `|` random-slope syntax in `MODEL POPULATION:`/`MODEL:` + `MODEL CONSTRAINT: NEW(...); m = ma*mb + cab;` to build the indirect-effect parameter — Example 12.11 |
| Multiple-group EFA, possibly with measurement invariance constraints on loadings/intercepts across groups | `MONTECARLO: NOBSERVATIONS = n1 n2; NGROUPS = 2;` + `MODEL POPULATION-g2:` for group-2-specific population values + `MODEL g2:` for group-2-specific analysis-model parameters (anything not restated in the group block stays equal across groups) — Example 12.12 |

## Menu path & screen fields
1. **MONTECARLO:** same required basics as the standard workflow (`NAMES`, `NOBSERVATIONS`, `NREPS`, `SEED`), plus whichever specialized options are triggered:
   - EFA analysis model: no extra `MONTECARLO` options — the specialization is in `MODEL:` (see Sub-option details)
   - Discrete-time survival with informative missingness: `GENERATE = u1-u4(1); MISSING = u2-u4; CATEGORICAL = u1-u4;`
   - Two-part outcome: `GENERATE = u1-u4(1); MISSING = y1-y4; CATEGORICAL = u1-u4;` (the `u` variables are the binary part, the `y` variables the continuous part)
   - Two-level continuous-time survival: `GENERATE = t(s 20*1); HAZARDC = t(.5); SURVIVAL = t(ALL); NCSIZES = 3; CSIZES = 40(5) 50(10) 20(15); WITHIN = x; BETWEEN = w;`
   - Two-level random-slope mediation: `WITHIN = x; NCSIZES = 1; CSIZES = 100(10);`
   - Multiple-group EFA: `NOBSERVATIONS = 500 500; NGROUPS = 2;`
2. **MODEL POPULATION:** (and, for multiple groups, additional `MODEL POPULATION-gN:` blocks) — the "true" data-generating model, with the specialized pieces below
3. **MODEL MISSING:** (discrete-time survival with censoring-after-event, and two-part outcome variants) — logistic model that manufactures the required missing-data pattern
4. **ANALYSIS:** `TYPE = TWOLEVEL;` / `TYPE = TWOLEVEL RANDOM;`, `BASEHAZARD = OFF;` (continuous-time survival), `ESTIMATOR = MLR;` as needed
5. **MODEL:** (and, for multiple groups, additional `MODEL gN:` blocks) — the analysis model actually fit to each replication
6. **MODEL CONSTRAINT:** (two-level random-slope mediation) — `NEW(...);` plus an algebraic expression defining the indirect-effect parameter
7. **OUTPUT:** `TECH8;` / `TECH9;` as in the basic workflow

## Sub-option details
- **EFA/ESEM analysis model (Example 12.5)**: data are generated from an ordinary fixed-loading CFA population model (`f1 BY y1-y7*.5; f2 BY y4-y5*.25 y6-y10*.8; f1-f2@1; f1 WITH f2*.5;`), but the analysis `MODEL:` re-specifies the factors as an EFA/ESEM set using `(*1)` after the `BY` statement list — e.g. `f1 BY y1-y7*.5 y8-y10*0 (*1); f2 BY y1-y3*.0 y4-y5*.25 y6-y10*.8 (*1);`. The `(*1)` label marks `f1` and `f2` as belonging to EFA set 1; with no `ROTATION` option specified in `ANALYSIS:`, Mplus applies the default oblique GEOMIN rotation to obtain loadings and factor correlations. Item intercepts and residual variances are estimated, residuals are uncorrelated by default, and factor variances are fixed at 1 (factors are allowed to correlate under the default oblique rotation). Default estimator is maximum likelihood.
- **Informative missingness for discrete-time survival (Example 12.8)**: `MONTECARLO: MISSING = u2-u4;` marks which generated dependent variables get missing data manufactured (the first period, `u1`, is never missing). `MODEL MISSING:` then specifies a logistic regression for a binary "is-missing" indicator per variable: `[u2-u4@-15];` sets the missingness intercepts so that, when all predictors are 0, the probability of being missing is essentially 0. `u2 ON u1@30; u3 ON u1-u2@30; u4 ON u1-u3@30;` fixes the logistic coefficients so large that a value of 1 on any earlier event-history indicator (i.e., the event already occurred) pushes the logit for the later indicator to roughly +15, making the probability that the later indicator is missing essentially 1. This reproduces the requirement that, for a non-repeatable event, indicators after the event has occurred must be scored missing for correct maximum-likelihood estimation.
- **Two-part/semicontinuous growth outcome (Example 12.9)**: two parallel sets of variables are generated together — `u1-u4` (binary "any/none" part, `GENERATE = u1-u4(1);`, `CATEGORICAL = u1-u4;`) and `y1-y4` (continuous "amount" part). `MODEL POPULATION:` defines a growth process for each part (`iu su | u1@0 u2@1 u3@2 u4@3;` for the binary-part intercept/slope, `iy sy | y1@0 y2@1 y3@2 y4@3;` for the continuous-part intercept/slope), and `iu WITH iy*0.9;` lets the two parts' random intercepts correlate. `MODEL MISSING:` then makes each `y` missing except when its paired `u` equals 1: `[y1-y4@15];` sets a base logit corresponding to "always missing," while `y1 ON u1@-30; y2 ON u2@-30; y3 ON u3@-30; y4 ON u4@-30;` drives the logit down to roughly -15 (probability of missing ≈ 0) whenever the paired `u` is 1. The net effect is that the continuous outcome is observed only in occasions where the binary part indicates a positive value, matching real two-part/semicontinuous data structure.
- **`HAZARDC` (MONTECARLO, Example 12.10)**: specifies the hazard used to generate an independent right-censoring process for a continuous time-to-event variable, e.g. `HAZARDC = t(.5);` generates a censoring indicator (0 = not censored, 1 = right-censored) with a censoring hazard of .5 for the time-to-event variable `t`.
- **`SURVIVAL` (MONTECARLO, Example 12.10)**: identifies the analysis variable(s) holding time-to-event information and, for the analysis model, the time intervals for the baseline hazard function; `SURVIVAL = t(ALL);` takes the time intervals directly from the generated data rather than specifying them explicitly.
- **`GENERATE = t(s 20*1);` (survival scale for data generation)**: the `s` designator marks `t` as a survival/time-to-event variable for data-generation purposes; `20*1` specifies that 20 discretized intervals of length 1 are used internally to generate the continuous-time data.
- **Frailty via a residual variance (Example 12.10)**: in a `TYPE = TWOLEVEL` continuous-time survival model, `%WITHIN%` has `t ON x;` (loglinear regression of time-to-event on the within-level covariate), while `%BETWEEN%` has `t ON w;` (regression of the between-level random intercept of `t` on the between-level covariate `w`) plus an estimated residual variance for `t` on the between level — this residual variance is the frailty parameter, capturing unexplained cluster-level heterogeneity in the hazard.
- **`BASEHAZARD` (ANALYSIS, Example 12.10)**: controls whether the baseline hazard in continuous-time survival is treated as non-parametric (`OFF`, the default) or as explicit estimated parameters (`ON`, as in the plain continuous-time survival file's parametric proportional-hazards variant).
- **Two-level random-slope mediation (Example 12.11)**: `ANALYSIS: TYPE = TWOLEVEL RANDOM;` estimates a multilevel model with random intercepts and random slopes. In `MODEL:`, the `|` symbol both names and defines each random slope from a within-level regression: `c | y ON x;` (total effect), `b | y ON m;` (b-path), `a | m ON x;` (a-path). On `%BETWEEN%`, the random slopes `a`, `b`, `c` (and the random intercepts of `y` and `m`) get variances (`y*1 m*1 a*1 b*1 c*1;`), means (`[a*0.4] (ma); [b*0.5] (mb); [c*0.6];`), and covariances via `WITH` statements — including `a WITH b*0.1 (cab);`, the covariance between the a-slope and b-slope, which matters for the indirect effect in a random-slope mediation model.
- **`MODEL CONSTRAINT: NEW(...)` for the indirect effect (Example 12.11)**: because the mediated (indirect) effect in a two-level random-slope model is not simply the product of two fixed coefficients, it is built by hand: `MODEL CONSTRAINT: NEW(m*0.3); m = ma*mb + cab;` defines a new parameter `m` equal to the product of the mean a-slope and mean b-slope plus the a/b slope covariance — the formula for a random-slope indirect effect. The chapter's introductory feature list also notes that ordinary (non-random-slope) indirect effects can instead be requested with the `MODEL INDIRECT` command; `MODEL CONSTRAINT`/`NEW` is used here specifically because the random-slope covariance term is not something `MODEL INDIRECT` computes automatically. Both `y` and `m` can also be specified as categorical outcomes in this design.
- **Multiple-group EFA (Example 12.12)**: `MONTECARLO: NOBSERVATIONS = 500 500; NGROUPS = 2;` generates two groups of 500 observations each (default group labels, no `GROUPING` variable needed for internal Monte Carlo). `MODEL POPULATION:` gives group-1 population values; a `MODEL POPULATION-g2:` block gives group-2-specific overrides (e.g. different factor variances, factor covariance, residual variances, factor means) — any parameter not restated there keeps its group-1 value. On the analysis side, `MODEL:` (the `(*1)` EFA-set analysis model) is the group-1 model, and `MODEL g2:` supplies group-2-specific parameters exactly the same way real-data multiple-group analyses work: parameters not repeated in `MODEL g2:` (here, the factor loadings) are held equal (invariant) across groups, while parameters repeated there (factor variances/covariance, residual variances, factor means) are allowed to differ.
- **EFA-specific caveat for population/analysis values**: when a factor is declared as an EFA set (the `(*1)` notation), asterisk-supplied values on the loading and factor-covariance parts of the `MODEL:` statement are used only to compute coverage — they are not usable as ordinary starting values, unlike in a CFA model.

## Post-run operations
- EFA Monte Carlo: read `MODEL RESULTS` as usual, but remember rotated loadings/factor correlations are what's being evaluated for bias/coverage/power — the population values in `MODEL POPULATION:` correspond to the fixed-loading CFA generating model, not directly to the rotated EFA loadings, so compare cautiously.
- Discrete-time survival with manufactured missingness: check that the `MODEL MISSING:` logistic coefficients produced the intended near-deterministic pattern (event-occurred ⇒ later periods missing) by inspecting simulated/observed missingness rates if in doubt; then read `f ON x` in `MODEL RESULTS` for power/bias as in an ordinary discrete-time survival Monte Carlo.
- Two-part/semicontinuous Monte Carlo: if the generated replications are saved (`REPSAVE = ALL; SAVE = ...;`) for a follow-up external analysis with `DATA TWOPART:`, a `DEFINE:` step is needed first — apply the exponential function to the continuous (`y`) variables (undoing the internal log-scale generation) and then recode the missing-data flag value (e.g. 999) to 0, representing the floor of the semicontinuous scale, before running the two-part analysis.
- Two-level continuous-time survival: inspect `t ON x` (within-level effect on the hazard), `t ON w` (between-level effect on the random intercept of the hazard), and the between-level residual variance of `t` (the frailty) for bias/coverage/power; a poorly identified frailty variance shows up as inflated `S.E. Average` or low `95% Cover` for that parameter.
- Two-level random-slope mediation: the constrained parameter `m` from `MODEL CONSTRAINT` appears in the `MODEL RESULTS`/`New/Additional Parameters` section of the output — its `% Sig Coeff` column is the Monte Carlo power estimate for the indirect effect; also check the individual `ma`, `mb`, and `cab` components for their own bias/power.
- Multiple-group EFA: check `MODEL RESULTS` separately by group; parameters intentionally held invariant (loadings) should show consistent recovery across both groups' generated data, while group-2-specific parameters (variances, factor means, etc.) should recover the values given in `MODEL POPULATION-g2:`/`MODEL g2:`.
- As in the basic workflow, request `OUTPUT: TECH9;` (and `TECH8;` for optimization history) to catch non-convergent or problematic replications before trusting the summary statistics, especially for the more complex multilevel/mixed-outcome variants in this file.

## Likely FAQ mapping
- "I want to simulate power/bias for an EFA or ESEM model, not a fixed-loading CFA" → Example 12.5: generate from a CFA population model, analyze with `(*1)` EFA-set notation in `MODEL:`
- "My outcome is time-to-event measured at only a few periods, and I need the event-history indicators to go missing correctly after the event happens" → Example 12.8: `MONTECARLO: MISSING =` + `MODEL MISSING:` with large fixed logistic coefficients
- "My outcome has a spike at zero plus a continuous amount when nonzero (semicontinuous/two-part)" → Example 12.9: paired binary (`u`) and continuous (`y`) variables, with `MODEL MISSING:` making `y` missing unless the paired `u` = 1
- "My survival data are clustered (e.g., patients within clinics) and I want a Cox-type model with a cluster-level frailty" → Example 12.10: `TYPE = TWOLEVEL` + `HAZARDC`/`SURVIVAL`/`GENERATE = t(s ...)` + a between-level residual variance on the time-to-event variable
- "I want power for an indirect (mediated) effect where the a-path and b-path vary randomly across clusters" → Example 12.11: `TYPE = TWOLEVEL RANDOM` + `|` random-slope syntax + `MODEL CONSTRAINT: NEW(...); m = ma*mb + cab;`, then read `% Sig Coeff` for `m`
- "I need to simulate a multiple-group EFA, possibly with invariant loadings/intercepts across groups" → Example 12.12: `NGROUPS =` + `MODEL POPULATION-gN:`/`MODEL gN:`, restating only the parameters that should differ by group
- "How do I choose which of these six specialized setups I need?" → see the Option selection logic table above
- "I already understand the basic Monte Carlo mechanics (NREPS, SEED, reading % Sig Coeff, etc.) — where's that covered?" → `monte-carlo-simulation-power.md`
